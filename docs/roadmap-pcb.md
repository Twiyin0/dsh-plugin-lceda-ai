### ~~P-06 布线~~ ✅ 已完成(网格 A*;推挤/差分/等长留待后续)

**结果**:`src/pcb/route.js` + `lceda-ai pcb route`。

- **原语**:`padRecord`/`trackRecord`/`viaRecord`(writer)+ `pathToCopper`(把栅格路径合并成走线段并在换层处生成过孔)
  + `mstOrder`(按曼哈顿距离把网络焊盘连成生成树)。
- **网格 A***:两层(可扩展)、4 邻域、换层代价可调;障碍 = 其他网络焊盘(按**真实包围盒**,含 POLYGON 焊盘)、
  已有走线/过孔、板框内缩。阻塞半径 = 间距 + 线宽/2 + 栅格(量化余量)。
- **出线口**:布线某网络时临时打开它自己焊盘的矩形区域,但**不打开会侵犯其他网络间距的格子**
  (0603 相邻焊盘只隔 6 单位,窗口会重叠)。
- **自检**:`verifyRouting` 用精确的线段↔矩形距离校验间距,并**按层判断**(底层走线从顶层 SMD 焊盘下方穿过是合法的)。

**实测**(v3 最小系统,13 器件 / 71 焊盘 / 40 网络,58.6×45.3mm):**33/40 网络布通**、75 段走线、75 过孔、
248mm 总长、**0 处间距违规**、106ms。编辑器打开确认:走线被渲染成带 net 的 polyline(RST/+5V/GND/XTAL1/XTAL2/PWR_LED…)、
76 个过孔、72 个焊盘。

**过程中发现并修掉的两个真 bug**:
1. 焊盘开口用的是「半径 = 半高的正方形」,把 10 单位外的相邻 DIP 焊盘一起解封 → 走线从邻居盘上穿过。
2. `POLYGON` 焊盘 width/height 为 0,真实形状在 `pointArr` 里 —— 路由器与自检都把它当成一个点。新增 `padBBox()` 统一处理。

**同时修正 P-03 的择优缺陷**:按封装名搜索时原来「取第一个能对上的候选」,导致 DIP-40 的 STC89C52RC 被配上
**LQFP-44(0.8mm 间距)**——0.254mm 规则下物理布不通。现在改为**给候选打分**(多出焊盘、焊盘数与引脚数之差、
封装名是否一致),完全匹配优先;并支持 `--footprint U1=<封装名>` 显式指定,报告里也会给出每个器件的**焊盘间距**,
间距过小且焊盘多于引脚时告警。

### ~~P-07 铺铜~~ ✅ 已完成(栅格洪泛 + 边界追踪;多边形偏置留作后续可选优化)

**结果**:`src/pcb/pour.js` + `lceda-ai pcb pour`。

- **区域**:板框内缩(默认 0.5mm);也可传 `region` 指定矩形。
- **避让**:其他网络的焊盘(按真实包围盒)、走线、过孔、已有铜皮,各自外扩间距后清空。
- **热焊盘**:同网络焊盘的四条辐条(默认 0.4mm 宽)穿过间距环,保证连通又不过分散热。
  **两遍处理**:先清全部障碍并记录其矩形,再开辐条,且**跳过会侵犯其他网络间距的格子**
  (D1 的 GND 盘与 PWR_LED 盘只隔 4 单位,间距环是重叠的)。
- **孤岛移除**:洪泛后只保留触及本网络焊盘的连通块;`--keep-island` 可保留最大块。
- **轮廓输出**:边界边链成闭环(**固定右转优先**,否则窄通道口会把凹口焊进外轮廓),
  带符号面积求和得到铜面积(孔洞环为负),简化共线点后写成 `COPPERAREA` 的 `pathStr`/`fillData`。
- **自检**:`verifyPour` 用**奇偶规则**判断“点在铜内”(正确排除孔洞),报告落在铜里的其他网络焊盘。

**实测**(v3 最小系统布线后):GND 铺铜 **1897.5 mm²**、23 个多边形、移除 1 个孤岛、**0 处越界**、22ms。
关掉热焊盘时铜全部成孤岛被移除(0 填充)—— 反向验证了孤岛逻辑。
编辑器打开确认:**23 个 `[copper_id]` 铜皮区域**(层 1)被正确识别。
注:编辑器 DOM 上的 `net` 属性要等它自己重算填充后才出现,记录里的 `net=GND` 是对的。

**过程中修掉的 3 个真 bug**:
1. 面积用 `abs()` 逐环相加 → 把孔洞也算成铜,得到比板子还大的面积;改用带符号面积。
2. 轮廓追踪「任选未用边」→ 在通道开口处跳到对面,把凹口焊进外轮廓,自检报 126 处假违规;
   改为**固定右转优先**的标准轮廓跟踪。
3. 热焊盘辐条压到相邻异网络焊盘的间距环 → 改为两遍处理 + 间距检查。

### ~~P-08 过孔~~ ✅ 已完成(通孔 + 缝合孔;盲孔/埋孔仅建模不生成)

**结果**:`src/pcb/via.js` + `lceda-ai pcb via`。

- **规则模型** `viaRules()`:盘径 / 钻孔 / 环宽 / 间距 / 孔到孔,来自板子的 DRC 块并支持按网络覆盖;
  还给出 `ok`(环宽 ≥ 0.05mm 才算可制造)。
- **过孔类型** `VIA_TYPES`:通孔 / 盲孔 / 埋孔都建模,但**只生成通孔** —— 盲埋孔需要板子声明内层,
  编辑器也只在特定叠层下提供,凭猜写层跨会产出板厂做不出来的文件。
- **缝合孔** `stitchVias()`:复用铺铜的栅格判断“哪里是铜”,按间距(默认 5mm)铺一层过孔栅格,
  要求周围有实心铜(不是一格窄条),并且**按过孔自身半径**校验与其他网络铜的精确距离。
- **自检** `verifyVias()`:间距(按所有层,因为通孔贯穿)与孔到孔。

**实测**(v3 最小系统布线+铺铜后):间距 5mm → 54 个缝合孔、3mm → 134 个、8mm → 14 个,**全部 0 违规**;
盘 0.508mm / 孔 0.254mm / 环 0.127mm。

**过程中修掉的一个真 bug(影响很大)**:`trackRecord` 只读 `strokeWidth`,而路由器写入的是 `width`
→ **所有自动布线都被写成默认 10 单位(2.54mm)宽**,而自检读的是内存里的 1 单位,所以一直“通过”。
修好后走线才是 0.254mm,铺铜面积也从 1897 → 1979mm²(走线变细、避让变少)。

### ~~P-10 Gerber 导出~~ ✅ 已完成(自研 RS-274X + Excellon,并用 gerbonara 独立校验)

**结论先说**:标准版的 Gerber 生成在编辑器内部是 `#worker_main` 这个 **web worker**,协议未公开,且导出要过原生保存对话框,
不可脚本化。因此 P-10 走**自研**路线 —— RS-274X / Excellon 都是 Ucamco / IPC-NC-349 **公开标准**,不属于“臆造私有格式”;
并且用第三方解析器 **gerbonara 1.6.3** 做独立校验(解析 + 渲染),不是自己验自己。

**结果**:`src/pcb/gerber.js` + `src/pcb/font.js` + `lceda-ai pcb gerber`。

- **层**:`F_Cu / B_Cu / F_SilkS / B_SilkS / F_Mask / B_Mask / Edge_Cuts` + `<name>.drl`(PTH,含过孔与插件焊盘孔)
  与 `<name>-NPTH.drl`(安装孔,无则不生成)。
- **格式**:`%FSLAX46Y46*%` + `%MOMM*%`(4.6 格式、毫米),`%TF.FileFunction%` 声明层用途,
  标准孔径 `C`/`R`/`O`,任意角度或 POLYGON 焊盘走 `G36/G37` 区域;铜皮按区域填充;走线用圆孔径描边。
- **坐标约定**:Gerber 的 **+Y 朝上**,板模型 +Y 朝下 → 以**板左下角为原点**输出(`makeTransform`)。
- **丝印文字**:编辑器的 TEXT 记录 `pathStr` 为空(它自己重画字形),所以自研了一个 **4×6 笔画字体**
  (`src/pcb/font.js`,数字/大写字母/常用符号),把位号与值真正画成丝印几何。
- **自检** `verifyGerber()`:flash 数与位置、描边段数、孔径是否都有定义、钻孔数、板框尺寸。

**实测**(v3 最小系统):8 个文件、自检全部一致;gerbonara **1239 个对象全部解析成功、8 个文件全部渲染**;
板框 59.566×46.306mm(= 58.55 + 线宽 1.016),顶层铜 57.912×44.704mm(= 板框 − 2×0.319 板边距),
钻孔 121 个(PTH:T1 0.508 / T2 0.254 / T3 0.889 / T4 1.100)。

**过程中抓到 3 个真 bug**:
1. **孔径未定义**:`apertureCode()` 先注册了 key,`useAperture()` 再判断“已存在”就跳过 → 所有 `%ADD%` 定义都没写出来,
   文件引用了不存在的 `D10`。**我自己的解析器不在乎,gerbonara 直接报错** —— 这正是引入独立校验的价值。
2. **整板垂直镜像**:直接输出板坐标,Gerber 是 +Y 向上 → 丝印文字上下颠倒、器件全在错误一侧。改为左下角原点 + Y 翻转。
3. **插件焊盘上重复打孔**:路由器在插件焊盘中心又放了过孔(焊盘本身已贯穿两层),DRC 报 **47 处孔到孔重叠**;
   修法是换层处若落在插件焊盘格上就不生成过孔(过孔数 63 → 16)。
   顺带发现 `copperItems` 没暴露焊盘的 `shape`/`holeR` —— 这曾导致**所有焊盘被写成矩形**且**插件焊盘的钻孔全部缺失**。

## 3. 风险与对策

| 风险 | 对策 |
|---|---|
| PCB 记录格式与原理图差异大 | 先采样再写码;解析器对未知记录兜底(已有 `unknown` 分支) |
| 自研 Gerber 出错导致打样报废 | M4 只做“编辑器导出 + 自检”;自研 Gerber 标为实验特性 |
| 自动布线质量差 | 先交付辅助布线;自动布线只承诺“简单双面板可布通” |
| 铺铜性能(大板多边形运算) | 用成熟裁剪库 + 栅格近似;必要时分块 |
| 生成的 PCB 编辑器不认 | 每个里程碑都用 CDP 打开真实编辑器验证一次 |
| 工具参数命名踩保留字 | 参数名避开 `title/description/type/...`,加回归测试(已有) |
