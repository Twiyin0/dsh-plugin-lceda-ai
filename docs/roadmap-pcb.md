## 0. 已知事实(来自 REA / 实测,不是猜测)

| 事实 | 来源 |
|---|---|
| 文档类型:`docType` 1=原理图, 2=符号, 3=PCB, 4=封装 | 解析实测 + 编辑器 API `packageDetail.docType` |
| 跨图纸连接用 **Net Port**(`place_part(netLabel_netPort)`,partId 含 `part_netLabel_netPort`,枚举 `ENETPORT`) | 编辑器 bundle `js/main.min.js` |
| NetLabel = 本图纸;NetFlag(电源/地)= 全局;NetPort = 跨图纸 | 同上 + 编辑器菜单项 `netLabel_GNd / netLabel_VCC / netLabel_netPort` |
| 封装可从商城接口取:产品接口返回 `packageDetail.uuid/docType=4` | `easyeda.com/api/products/{LCSC}/components` |
| 编辑器可被 CDP 驱动(`--remote-debugging-port`),内部通道 `postMessage({type:'editDocJson'})` 可打开文档 | 本项目已验证 |
| PCB 记录格式(线/焊盘/过孔/铜皮)**尚无样本** | 待采样,见 P-01 |

**采样办法(P-01 的第一步)**:打开立创EDA → 新建 PCB → 放一个封装、画一段线、放一个过孔、铺一块铜 →
`文件 → 保存` → 读取本地 `PCB_1.json`。用 CDP 把该文件抓回来即可得到权威格式,避免猜。

### ~~P-03 封装(Footprint)管理~~ ✅ 已完成

**结果**:`src/pcb/footprint.js` + `lceda-ai pcb fp` / `pcb map`。两条解析路径:立创编号走产品接口的
`packageDetail.uuid`(符号与封装是两份独立文档,只有这里能对应上);标准库通用符号没有编号,则**按封装名**
在标准库封装类目(`doctype[]=4`)里搜候选,逐个取回并用“引脚↔焊盘”校验挑出真正匹配的那个。

校验语义:符号引脚没有对应焊盘 = **错误**(装不上);封装多出焊盘(散热盘/固定盘/字母盘)= **提示**。

实测 v3 最小系统 13 个器件:13 匹配、0 引脚不符、0 缺失(U1 的 DIP-40 封装多出 41–44 固定盘,LED 是 C/A 字母盘)。
封装文档按 `fp` 类型落盘缓存(30 天)。测试 7 项 + e2e 4 项。

### (原计划) P-03 封装(Footprint)管理
- 目标:封装库索引、按 LCSC/uuid 取封装、原理图器件 ↔ 封装映射与校验(引脚数/焊盘号)、封装缺失报告。
- 方案:
  - **A(推荐)** `packageDetail.uuid` → `GET /api/components/{uuid}` 取 `docType 4` 文档,落盘缓存;建立“符号引脚号 ↔ 焊盘号”一致性检查。
  - B 维护本地封装库目录(用户自备 `.elib`/json),工具只索引。
  - C 自动生成封装(按 IPC-7351 从封装名推焊盘尺寸)——准确度风险大,放最后。
- 验证:对 v3 示例 13 个器件做映射,报告缺失/引脚不匹配;命中率应 100%(标准库器件)。

### P-04 原理图 → PCB(网表传递与工程骨架)
- 目标:由原理图工程生成 `PCB_1.json`:放置所有器件封装、建立网络表、按 Room/分页分组。
- 方案:
  - **A(推荐)** 复用编辑器:用 CDP 触发“原理图 → 转 PCB”,再抓回生成物作为参考;工具只做**校验与批量修补**(比生成更稳)。
  - B 自己写 PCB 生成器(需要 P-01 完成),把器件按网表摆放 + 生成飞线;可控性最好,风险最高。
  - C 混合:工具生成骨架(器件+网络),复杂部分交给编辑器。
- 验证:生成的 PCB 在编辑器里打开无 ERC 错;网络数与原理图一致。

### P-05 元件布局
- 目标:自动/半自动摆放:按功能分区、去耦电容贴引脚、连接器靠板边、按网表聚簇、避免重叠与越界。
- 方案:
  - **A(推荐)** 把原理图侧 `src/layout.js` 的思路搬到 PCB:锚点 + 网表分侧 + 栅格打包;额外加“去耦电容靠近电源脚”规则。
  - B 力导向/模拟退火(线长最小化),效果更好但慢、结果不稳定。
  - C 规则模板(用户给区域约束,如“J1 在左边距 5mm”),工具只做约束求解。
- 验证:无重叠、在板框内、平均飞线长度优于随机摆放;输出布局报告。

### P-06 布线
- 目标:先做**辅助**(推挤、差分对、等长、总线扇出、自动扇出 BGA),再考虑自动布线。
- 方案:
  - **A(推荐)** 交互式原语:单段/多段走线、过孔跳层、45° 拐角、线宽按网络类;DRC 实时校验。
  - B 网格迷宫自动布线(A* + rip-up & reroute):可控、可测,但只适合简单板。
  - C 接入外部布线器(KiCad `freerouting` 等)导出 DSN 再导回——生态成熟,依赖外部工具。
- 验证:布通率、DRC 零违例、与编辑器打开一致。

### P-07 铺铜
- 目标:整板/区域铺铜、网络绑定(通常 GND)、间距与热焊盘、孤岛移除、铜皮到板框间距。
- 方案:
  - **A(推荐)** 多边形偏置 + 扫描线填充:用 `clipper-lib`(或 `martinez-polygon-clipping`)做 clearance 偏置,再填充;热焊盘用规则生成。
  - B 栅格洪泛填充(实现最简单,边缘毛刺,适合原型)。
  - C 转发给编辑器铺铜(最省事,离线不可用)。
- 验证:铜皮与所有非同网络对象间距 ≥ 规则值;孤岛被移除;编辑器打开无 DRC 报错。

### P-08 过孔
- 目标:放置/批量放置过孔(换层、缝合孔、散热孔),按网络类约束孔径/环宽/间距。
- 方案:
  - **A(推荐)** 规则化:过孔类型表(通孔/盲埋孔预留)+ 缝合孔沿板边/铜皮栅格自动生成。
  - B 交互式放置 + DRC 校验(先做,最简单)。
  - C 自动布线时由布线器决定(依赖 P-06B)。
- 验证:孔径/环宽符合规则;缝合孔间距达标;DRC 通过。

### P-09 Layout / DRC 规则引擎
- 目标:设计规则(线宽、间距、过孔、孔到孔、丝印压焊盘、板边距)与检查报告;支持网络类(电源加宽)。
- 方案:
  - **A(推荐)** 纯几何实现:线段-线段距离、点-多边形、圆-矩形;规则用 JSON 配置;输出可点击的违规清单。
  - B 复用 KiCad 的 DRC 规则语义(便于迁移用户)。
  - C 只做子集(间距/线宽/孔),其余交给编辑器。
- 验证:构造已知违例板,检查全部被报出且无误报。

### P-10 Gerber 导出
- 目标:输出 RS-274X + Excellon 钻孔 + 贴片坐标,或直接由编辑器导出。
- 方案:
  - **A(推荐)** 转发编辑器导出(最可靠),工具负责:参数校验、批量命名、导出后自检(层齐全、文件非空、孔径表一致)。
  - B 自研 Gerber 写出器:从 P-01 模型直接生成,完全离线可控;需要吃透 aperture/极性/弧线。
  - C 用 `pcb-tools`(Python)等第三方库转换。
- 验证:导出的 Gerber 用第三方查看器/编辑器反向导入无误;与编辑器导出的层做逐层比对。

### P-11 BOM 导出
- 目标:PCB 版 BOM(位号、值、封装、LCSC、数量、位号分组)+ 贴片坐标(CPL/POS)+ Excel/CSV。
- 方案:
  - **A(推荐)** 复用现有 BOM + 封装映射,输出 CSV/XLSX(已有 `office-xlsx` 能力),并生成嘉立创/立创商城下单列(LCSC 编号)。
  - B 只出 CSV,交给用户自己整理。
  - C 直接对接嘉立创下单格式(需要其模板,风险高,最后做)。
- 验证:位号齐全、数量与原理图一致、坐标可被贴片厂解析。

## 3. 风险与对策

| 风险 | 对策 |
|---|---|
| PCB 记录格式与原理图差异大 | 先采样再写码;解析器对未知记录兜底(已有 `unknown` 分支) |
| 自研 Gerber 出错导致打样报废 | M4 只做“编辑器导出 + 自检”;自研 Gerber 标为实验特性 |
| 自动布线质量差 | 先交付辅助布线;自动布线只承诺“简单双面板可布通” |
| 铺铜性能(大板多边形运算) | 用成熟裁剪库 + 栅格近似;必要时分块 |
| 生成的 PCB 编辑器不认 | 每个里程碑都用 CDP 打开真实编辑器验证一次 |
| 工具参数命名踩保留字 | 参数名避开 `title/description/type/...`,加回归测试(已有) |
